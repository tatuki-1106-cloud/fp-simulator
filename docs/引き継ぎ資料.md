## 1. 現状のサマリ

FP-UNIVライクな日本のライフプラン・シミュレーター。月次キャッシュフロー計算エンジン + FastAPI/Jinja2/HTMXのWeb UI + MCPサーバー(AI連携)を実装済み。Cloud Runにデプロイ済み。

### 実装済み機能

| 分野 | 内容 |
|---|---|
| 計算エンジン | 月次CF、所得税(年末調整モデル)、住民税(翌年6月〜)、社会保険(厚生年金/健保/介護/雇用、都道府県別)、老齢年金(基礎+厚生+繰上/繰下+加給)、退職金(分離課税) |
| 拡張機能 | 住宅ローン(元利/元金均等・繰上返済・ボーナス払い・据置・住宅ローン控除)、教育費(公立/私立パス)、iDeCo/NISA、保険、産休育休(計算のみ) |
| UI | 2カラムレイアウト(左サイドバーQ1〜Q11)、ライフマップ(タイムライン)、年次CF表、貯蓄残高グラフ(Chart.js)、前提条件表示 |
| MCP | 8ツール(list/get/update_household, run_simulation, get_cashflow, explain_amount, list/get_tax_parameter) |
| パラメータ | YAML時系列管理(出典URL必須)、OpenFisca方式 |
| テスト | 84テスト(ゴールデンマスタ回帰テスト含む) |
| デプロイ | Cloud Run + Litestream(GCSバックアップ)、Dockerfile/entrypoint.sh |

## 3. 既知の課題・改善点

### 3.1 セキュリティ(最優先)

| 課題 | 内容 | 対策案 |
|---|---|---|
| **IAPの構成確認** | Cloud Run直接IAP + カスタムOAuthで運用中 | IAP設定変更時は許可ユーザーとCloud Run Invokerを確認 |
| **MCPの認証** | `/mcp/` はAPIキー認証 | Secret Managerの参照権限とキー更新手順を確認 |
| **入力検証** | フォームのバリデーションが最小限 | pydanticのバリデーション強化、金額の上限チェック |

### 3.2 計算精度

| 課題 | 内容 | 対策案 |
|---|---|---|
| **源泉徴収の月次モデル** | 「年間推定/12 + 12月年末調整」の簡易モデル | 実際の源泉徴収税額表(月額表・甲欄)による月次計算に改善 |
| **住民税の前年所得推定** | 前年の社保を現在の月次値×12で推定 | 前年の実績値を保持する設計に変更 |
| **配偶者控除** | 配偶者収入を0扱い | 配偶者の収入も考慮した判定に |
| **標準報酬月額テーブル** | 主要区分のみの簡易版 | 完全な等級テーブルをYAMLパラメータ化 |
| **iDeCo/NISAの資産追跡** | 掛金・投資額と運用残高を分離表示済み | 受取時課税・商品別残高・売却を追加 |
| **産休育休のCF統合** | 計算エンジンのみ、CFに未統合 | 休業期間中の給与→給付金への置き換えを実装 |

### 3.3 UI/UX

| 課題 | 内容 | 対策案 |
|---|---|---|
| **月次ドリルダウン** | 年次表から月次詳細へ遷移可能 | 将来HTMXによる展開表示へ改善 |
| **表示範囲切替** | 全期間表示のみ | 1年/3年/5年/10年の切替(FP-UNIV準拠) |
| **前提条件の変更UI** | プラン比較画面で物価上昇率・運用利回りを変更可能 | 収入・支出・退職年齢などへ拡張 |
| **プラン比較** | 現行プランと変更プランを並列比較可能 | 複数プランの保存・再利用 |
| **万が一シナリオ** | 対象者と万が一年齢を指定して、生きる道と比較可能 | 遺族年金・児童手当・万が一時の生活費を統合 |
| **保存履歴・プランコピー** | 未実装 | FP-UNIVにある機能 |
| **Excel/CSVエクスポート** | 未実装 | CF表のエクスポート |
| **モバイル対応** | 基本レスポンシブのみ | スマホでの入力UX改善 |

### 3.4 データ・運用

| 課題 | 内容 | 対策案 |
|---|---|---|
| **データの永続性** | Cloud Runの /app/data はエフェメラル | Litestreamのリストアが正しく動作するか検証・runbook化 |
| **変更履歴** | audit_log未実装 | MCP/AIによる変更を追跡するテーブル |
| **バックアップ検証** | Litestreamのリストアテスト未実施 | 定期的なリストア訓練 |
| **ヘルスチェック** | アプリの `/healthz` は存在するが、本番IAPフロントエンド経由ではGoogle Frontendの404になる | Cloud Runのリクエスト/エラー、ログ、リビジョン状態で監視 |

## 4. 追加候補の機能(優先度順)

### 高優先(実用性が高い)

1. **本番認証の完成** — IAPまたは独自認証で身内のみアクセス可能に
2. **月次ドリルダウン** — 年次表から月次明細への展開
3. **プラン比較** — 複数シナリオの並列表示(FP-UNIVの主要機能)
4. **万が一シナリオの精緻化** — 遺族年金・死亡保険金・必要保障額分析
5. **iDeCo/NISAの精緻化** — 受取時課税・商品別残高・売却を追加

### 中優先(差別化・利便性)

6. **計算トレーサビリティのUI** — 「この金額の根拠は?」をクリックで表示(explain_amountのフロント)
7. **税制改正ウォッチャー** — AIによる改正情報収集→パラメータ差分PRの自動生成(§9.4)
8. **仮説シナリオ** — 「消費税15%になったら」等のパラメータ差分シミュレーション
9. **Excel/CSVエクスポート** — CF表のダウンロード
10. **児童手当** — 2024年10月改正対応の自動計算

### 低優先(ニッチ・大規模)

11. **不動産投資分析** — 減価償却・投資指標(GPI/NOI等)
12. **モンテカルロシミュレーション** — 運用リターンの確率分布
13. **譲渡所得** — 株式・不動産の譲渡
14. **高額療養費** — 医療費の上限
15. **相続税** — 独立した相続税シミュレーション

## 5. 技術的負債・リファクタリング候補

| 項目 | 内容 |
|---|---|
| **cashflow.pyの肥大化** | simulate()が長大(300行超)。収入/税/支出/ローン等をサブ関数に分割 |
| **年齢計算の統一** | `age_at` と `age_at_year_end` が混在。年末基準か月基準かを整理 |
| **エラーハンドリング** | 計算エラー時のフォールバックがない。ユーザーフレンドリーなエラー表示 |
| **パフォーマンス** | ローンスケジュールを毎月計算している(loan_scheduleを事前計算してキャッシュ) |
| **テストのカバレッジ** | CF統合テストはあるが、エッジケース(赤字・高齢・多拠点等)が不足 |
| **型安全性** | engine関数の引数に `Any` が残っている箇所の型付け |

## 6. 運用情報

### ローカル起動

```powershell
Set-Location C:\Project\FP_Simulator
pip install -e ".[dev]"
pytest  # 81テスト
uvicorn fp_simulator.web.main:app --reload --port 8000
```

### 本番デプロイ

```powershell
# gcloud認証済みの前提
gcloud config set project fp-simulator
gcloud builds submit --tag asia-northeast1-docker.pkg.dev/fp-simulator/fp-simulator/app:latest
gcloud run deploy fp-simulator --image asia-northeast1-docker.pkg.dev/fp-simulator/fp-simulator/app:latest --region asia-northeast1 --max-instances 1
```

### 本番監視

Cloud Monitoringに次の5xxアラートポリシーを作成済み。

- ポリシー: `FP Simulator Cloud Run 5xx responses`
- 条件: `fp-simulator` の5xxレスポンスが5分間継続
- 通知: 所有者メール通知チャンネル（初回はメールの確認が必要）
- 定義ファイル: `deploy/monitoring/cloud-run-5xx-alert-policy.json`

`/healthz` はアプリ単体では200を返すが、本番のIAP/Google Frontend経由では転送されないため、公開Uptime Checkには使用しない。障害時は次を確認する。

```powershell
gcloud run services describe fp-simulator --region asia-northeast1 --project fp-simulator
gcloud run revisions list --service fp-simulator --region asia-northeast1 --project fp-simulator
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="fp-simulator"' --project fp-simulator --limit 50
```

アラートポリシーと通知チャンネルの管理はCloud Monitoringコンソールでも行える。
