## 1. 現状のサマリ

FP-UNIVライクな日本のライフプラン・シミュレーター。月次キャッシュフロー計算エンジン + FastAPI/Jinja2/HTMXのWeb UI + MCPサーバー(AI連携)を実装済み。Cloud Runにデプロイ済み。

### 実装済み機能

| 分野 | 内容 |
|---|---|
| 計算エンジン | 月次CF、所得税(年末調整モデル)、住民税(翌年6月〜)、社会保険(厚生年金/健保/介護/雇用、都道府県別)、老齢年金(基礎+厚生+繰上/繰下+加給)、退職金(分離課税) |
| 拡張機能 | 住宅ローン(元利/元金均等・繰上返済・ボーナス払い・据置・住宅ローン控除)、教育費(公立/私立パス)、iDeCo/NISA、保険、産休育休(計算のみ) |
| UI | 2カラムレイアウト(左サイドバーQ1〜Q11)、ライフマップ(タイムライン)、年次CF表、貯蓄残高グラフ(Chart.js)、前提条件表示 |
| MCP | 8ツール(list/get/update_household, run_simulation, get_cashflow, explain_amount, list/get_tax_parameter) |
| パラメータ | YAML時系列管理(出典URL必須)、OpenFisca方式 |
| テスト | 112テスト(ゴールデンマスタ回帰テスト・cashflowヘルパー単体テスト含む) |
| デプロイ | Cloud Run + Litestream(GCSバックアップ)、Dockerfile/entrypoint.sh。最新リビジョン: `fp-simulator-00036-m72` (100%トラフィック) |

## 3. 既知の課題・改善点

### 3.1 セキュリティ(最優先)

| 課題 | 内容 | 対策案 |
|---|---|---|
| **IAPの構成確認** | Cloud Run直接IAP + カスタムOAuthで運用中 | IAP設定変更時は許可ユーザーとCloud Run Invokerを確認 |
| **MCPの認証** | `/mcp/` はAPIキー認証 | Secret Managerの参照権限とキー更新手順を確認 |
| **入力検証** | フォームのバリデーションが最小限 | pydanticのバリデーション強化、金額の上限チェック |

### 3.2 計算精度

| 課題 | 内容 | 対策案 |
|---|---|---|
| **源泉徴収の月次モデル** | 「年間推定/12 + 12月年末調整」の簡易モデル | 実際の源泉徴収税額表(月額表・甲欄)による月次計算に改善 |
| **住民税の前年所得推定** | 前年の社保を現在の月次値×12で推定 | 前年の実績値を保持する設計に変更 |
| **配偶者控除** | 配偶者収入を0扱い | 配偶者の収入も考慮した判定に |
| **標準報酬月額テーブル** | 主要区分のみの簡易版 | 完全な等級テーブルをYAMLパラメータ化 |
| **iDeCo/NISAの資産追跡** | 掛金・投資額・運用残高を分離し、明示した受取開始年齢・月額で取崩し可能。iDeCoは入力税率を概算適用、NISAは非課税扱い | 制度要件に基づく受取時課税、商品別残高、売却 |
| **産休育休のCF統合** | 計算エンジンのみ、CFに未統合 | 休業期間中の給与→給付金への置き換えを実装 |

### 3.3 UI/UX

| 課題 | 内容 | 対策案 |
|---|---|---|
| **月次ドリルダウン** | 年次表から月次詳細へ遷移可能。年次集計・前年/翌年ボタン＋年セレクトボックスのナビゲーション。月次表は主要8列(年月/年齢/収入/税・社保/支出/収支/月末残高)に削減し、乗り物・住宅・iDeCo/NISAなどの詳細列は「内訳・計算根拠」展開内に非ゼロ項目だけ金額内訳として表示。TraceEntryの判定・根拠JSON・公式出典リンクも従来どおり確認可能 | 出典対象パラメータの拡充 |
| **表示範囲切替** | 1年/3年/5年/10年/全期間を切替可能。サマリー・エクスポートは生涯全体 | 年齢基準・現在位置基準などの表示起点切替 |
| **結果の視覚化** | 重要指標(最低残高・最終金融資産・判定)をカード表示し、赤字時は赤で強調。年次収入構成の積み上げ棒グラフと生涯支出内訳のドーナツグラフ(いずれも生涯全体で固定)を追加 | グラフの期間切替、支出カテゴリの細分化 |
| **Q6〜Q8タブ** | Q6所有住宅、Q7乗り物、Q8ライフイベント（汎用・結婚援助・葬儀費）を計算へ統合 | Q8イベントの編集・家族別年齢指定を拡張 |
| **前提条件の変更UI** | プラン比較画面で物価上昇率・運用利回りを変更可能 | 収入・支出・退職年齢などへ拡張 |
| **プラン比較** | 現行プランと変更プランを並列比較可能 | 保存済みプラン同士の比較 |
| **万が一シナリオ** | 対象者と万が一年齢を指定し、遺族年金(加入記録・家族情報から簡易自動計算)・児童手当・生活費削減率を死亡月以降に反映して比較可能。死亡後の最低残高から追加必要保障額を表示 | 未納月数・死亡原因・生計維持などの詳細入力による厳密判定 |
| **保存履歴・プランコピー** | 保存・一覧・コピー・結果表示・復元・削除を実装。保存済みプラン同士の年次比較にも対応 | 指標の差分表示、監査ログ |
| **Excel/CSVエクスポート** | 年次・月次のキャッシュフローをCSV/Excelでダウンロード可能 | 書式・グラフ付き帳票の強化 |
| **モバイル対応** | 720px以下でQ1〜Q11ナビゲーションを横スクロール可能なタブ型に変更。入力欄・ボタンは44pxタップ領域、フォームは画面幅に追従。表は全画面で個別に横スクロール(デスクトップでの20列年次表の横溢れも解消)、グラフ・ライフマップもスマホ幅に調整 | 実機での主要画面確認、必要に応じたカード型表示 |

## 4. 追加候補の機能(優先度順)

### 高優先(実用性が高い)

1. **本番認証の完成** — IAPまたは独自認証で身内のみアクセス可能に
2. **月次ドリルダウン** — 年次集計・年移動・項目別計算根拠表示まで実装済み
3. **プラン比較** — 複数シナリオの並列表示(FP-UNIVの主要機能)
4. **万が一シナリオの制度対応** — 遺族年金の簡易受給判定・公式パラメータ計算・追加必要保障額分析を実装済み。詳細入力による厳密判定が残課題
5. **iDeCo/NISAの制度対応** — 受取時課税・商品別残高・売却を追加

### 中優先(差別化・利便性)

6. **保存プランの比較強化** — 保存済みプラン同士の差分・並列比較
7. **計算トレーサビリティのUI** — 月次明細で項目・金額・判定・根拠JSON・公式出典リンクを確認可能
8. **税制改正ウォッチャー** — AIによる改正情報収集→パラメータ差分PRの自動生成(§9.4)
9. **仮説シナリオ** — 「消費税15%になったら」等のパラメータ差分シミュレーション
10. **Excel/CSVエクスポート** — CF表のダウンロード
11. **児童手当** — 2024年10月改正対応の自動計算を実装済み。公式パラメータは `parameters/child_allowance.yaml`

### 低優先(ニッチ・大規模)

11. **不動産投資分析** — 減価償却・投資指標(GPI/NOI等)
12. **モンテカルロシミュレーション** — 運用リターンの確率分布
13. **譲渡所得** — 株式・不動産の譲渡
14. **高額療養費** — 医療費の上限
15. **相続税** — 独立した相続税シミュレーション

## 5. 技術的負債・リファクタリング候補

| 項目 | 内容 |
|---|---|
| **cashflow.pyの肥大化** | `FinancingContext`、`_prepare_financing()`、`_apply_work_income()`、`_apply_pension_and_disaster_income()`、`_apply_income_tax()`、`_apply_resident_tax()`、`_apply_expenses()`、`_apply_education_expenses()`、`_apply_investments()`、`_apply_insurance()`、`_apply_housing()`、`_apply_vehicle_expenses()`へ責務を分割済み |
| **年齢計算の統一** | 月次判定は各月1日時点の`age_at`、前年所得の年次判定は12月31日時点の`age_at_year_end`に統一済み。所得税の推定年収も勤労収入と同じ月1日基準に揃えたため、誕生月(誕生日2日以降)で開始年齢に達する収入はその月の推定年収に含めない(テストで固定) |
| **エラーハンドリング** | 計算エラー時のフォールバックがない。ユーザーフレンドリーなエラー表示 |
| **パフォーマンス** | ローンスケジュールを毎月計算している(loan_scheduleを事前計算してキャッシュ) |
| **テストのカバレッジ** | CF統合テストはあるが、エッジケース(赤字・高齢・多拠点等)が不足 |
| **型安全性** | `TraceEntry`の根拠値と生存判定コールバックを型付け済み。パラメータスナップショットの`Any`は外部ローダー仕様として残存 |

### 5.1 公式モデル・代表世帯ベンチマーク

精度検証用に、次の2層で回帰テストを保持している。

- 公式値: 国税庁の給与所得控除・所得税・住民税の計算例、日本年金機構の老齢基礎年金・厚生年金モデル値
- 代表世帯: 会社員(年収600万円)・専業配偶者・子1人、住宅ローン・車両費・保険・生活費を組み合わせた2025年開始の月次CF

公式値の出典:

- 国税庁「給与所得控除」: https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1410.htm
- 日本年金機構「令和7年度の年金額改定」: `parameters/pension.yaml` に出典URLを記録
- 厚生年金・社会保険料率: `parameters/social_insurance.yaml` に出典URLを記録

代表世帯ベンチマークは制度計算の正しさを単独で証明するものではなく、公式値を含む複数機能の連携、月境界、年次集計、残高更新を検知するために使用する。

## 6. 運用情報

### ローカル起動

```powershell
Set-Location C:\Project\FP_Simulator
pip install -e ".[dev]"
pytest  # 112テスト
uvicorn fp_simulator.web.main:app --reload --port 8000
```

### 本番デプロイ

```powershell
# gcloud認証済みの前提
gcloud config set project fp-simulator
gcloud builds submit --tag asia-northeast1-docker.pkg.dev/fp-simulator/fp-simulator/app:latest
gcloud run deploy fp-simulator --image asia-northeast1-docker.pkg.dev/fp-simulator/fp-simulator/app:latest --region asia-northeast1 --max-instances 1
```

### 本番監視

Cloud Monitoringに次の5xxアラートポリシーを作成済み。

- ポリシー: `FP Simulator Cloud Run 5xx responses`
- 条件: `fp-simulator` の5xxレスポンスが5分間継続
- 通知: 所有者メール通知チャンネル（初回はメールの確認が必要）
- 定義ファイル: `deploy/monitoring/cloud-run-5xx-alert-policy.json`

`/healthz` はアプリ単体では200を返すが、本番のIAP/Google Frontend経由では転送されないため、公開Uptime Checkには使用しない。障害時は次を確認する。

```powershell
gcloud run services describe fp-simulator --region asia-northeast1 --project fp-simulator
gcloud run revisions list --service fp-simulator --region asia-northeast1 --project fp-simulator
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="fp-simulator"' --project fp-simulator --limit 50
```

アラートポリシーと通知チャンネルの管理はCloud Monitoringコンソールでも行える。
